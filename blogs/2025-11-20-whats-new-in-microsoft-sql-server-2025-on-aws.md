<p>As enterprises of all sizes accelerate their cloud transformation journeys, running <a href="https://aws.amazon.com/microsoft/sql-server/">Microsoft SQL Server on Amazon Web Services (AWS)</a> has emerged as a strategic choice for mission-critical database workloads, with <a href="https://d1.awsstatic.com/whitepapers/US51573923-IDC_Running_SQL_Server_Workloads_in_the_Cloud_2024.pdf">AWS emerging as a lead cloud provider for SQL Server users</a>. Whether deploying <a href="https://docs.aws.amazon.com/sql-server-ec2/latest/userguide/sql-server-on-ec2-overview.html">SQL Server on Amazon EC2 instances</a> for maximum control and customization, or leveraging the <a href="https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Welcome.html">managed database capabilities of Amazon RDS for SQL Server</a> to reduce administrative overhead, AWS offers flexible options that align with diverse business needs.</p> 
<p>Microsoft released SQL Server 2025 for general availability on November 18th 2025, with features and enhancements that improve database backups and availability, optimized database operations and performance, and developer experience.</p> 
<p>You can now deploy and run SQL Server 2025 on AWS, leveraging the <a href="https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2025?view=sql-server-ver17">new features and enhancements of SQL Server 2025</a>, while continuing to take advantage the benefits of AWS such as improved performance, simplified management, and reduced Total Cost of Ownership (TCO). <a href="https://aws.amazon.com/windows/resources/licensing/">Deploy SQL Server on AWS</a> and bring your own license (BYOL) to maximize existing investments or leverage the pay-as-you-go, <a href="https://docs.aws.amazon.com/sql-server-ec2/latest/userguide/sql-server-on-ec2-amis.html">license-included (LI) AWS provided SQL Server 2025 Amazon Machine Image</a> (AMI) option to eliminate the hassle of managing license compliance.</p> 
<p><strong>SQL Server Editions and feature updates</strong></p> 
<p>SQL Server 2025 includes <a href="https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2025?view=sql-server-ver17">Standard Developer and Enterprise Developer editions</a> to support application development and testing in non-production environments <a href="https://aws.amazon.com/windows/faq/#topic-3">without requiring Microsoft Developer Network (MSDN) licensing</a>. These editions enable developers to build and test applications in an environment that feature match their corresponding paid editions, eliminating SQL Server licensing cost in non-production environments. AWS customers can leverage <a href="https://aws.amazon.com/blogs/modernizing-with-aws/automating-sql-server-developer-deployments/">AWS automation</a> or <a href="https://aws.amazon.com/blogs/modernizing-with-aws/simplify-sql-server-developer-edition-deployments-with-aws-launch-wizard/">AWS Launch Wizard for SQL Server development edition</a> to deploy SQL Server Developer edition on EC2. To continue to drive down the Total Cost of Ownership in these environments, consider deploying your SQL Server 2025 development environments on AWS running on <a href="https://learn.microsoft.com/en-us/sql/linux/sql-server-linux-setup?view=sql-server-ver17">Linux or Docker containers</a>, eliminating Windows licensing cost.</p> 
<p>SQL Server 2025 Standard edition increased its resource limits to support up to 32 CPU cores and 256GB RAM. When deploying your SQL Server 2025 Standard edition databases on EC2, you should consider a <a href="https://aws.amazon.com/ec2/instance-types/memory-optimized/">Memory Optimized EC2 instance</a>, such as a r8i.8xlarge instance providing 32 vCPU and 256GB RAM; matching the edition resource limitations. Resource Governor, once only available in Enterprise edition, is now also available in Standard edition. Resource Governor allows DBAs to limit CPU, Memory, IOPS, number of running request, etc. for a specific workload, enabling safeguards against runaway workloads.</p> 
<p>SQL Server Web edition, used by Web hosters, has been removed from the <a href="https://learn.microsoft.com/en-us/sql/sql-server/editions-and-components-of-sql-server-2025">SQL Server 2025 edition catalogue</a>.</p> 
<p><strong>Database Backup and Availability Improvements</strong></p> 
<p>With SQL Server 2025, you can run <a href="https://learn.microsoft.com/en-us/sql/database-engine/availability-groups/windows/active-secondaries-backup-on-secondary-replicas-always-on-availability-groups?view=sql-server-ver17#new-for-sql-server-2025">your SQL Server database backups</a> (full, differential, and transaction log), from a secondary replica in your Always On Availability Groups. This helps offload storage, CPU, and network performance from the primary database host to a secondary host, reallocating database maintenance resources, and allowing it to be used by application queries. SQL Server 2025 also includes a new, more efficient, <a href="https://learn.microsoft.com/en-us/sql/relational-databases/backup-restore/backup-compression-sql-server?view=sql-server-ver17#zstd-compression-algorithm-introduced-in-sql-server-2025">ZSTD backup compression algorithm compared to the default MS_XPRESS algorithm,</a> increasing compression and minimizing backup storage footprint. Combining these new features with <a href="https://aws.amazon.com/blogs/modernizing-with-aws/backup-sql-server-to-amazon-s3/">SQL Server native backup to Amazon S3</a>, released in SQL Server 2022, you can <a href="https://docs.aws.amazon.com/prescriptive-guidance/latest/optimize-costs-microsoft-workloads/sql-server-backup.html">build a robust backup strategy on AWS</a> to support your database backup and restore requirements including local recovery, environment refreshes, compliance archival with <a href="https://aws.amazon.com/s3/storage-classes/glacier/">Amazon S3 Glacier</a>, ransomware protection with <a href="https://aws.amazon.com/s3/features/object-lock/">Amazon S3 Object lock</a>, storage based snapshots for quick recovery with <a href="https://docs.aws.amazon.com/ebs/latest/userguide/ebs-snapshots.html">Amazon EBS snapshots</a>, copying native backups “offsite” for remote recovery via <a href="https://docs.aws.amazon.com/AmazonS3/latest/userguide/replication.html">S3 Cross-Region Replication</a>, etc.</p> 
<p>If you are leveraging <a href="https://learn.microsoft.com/en-us/sql/database-engine/availability-groups/windows/distributed-availability-groups">Distributed Availability Groups</a> (DAG) in SQL Server 2025 you can see improved synchronization performance, by <a href="https://learn.microsoft.com/en-us/sql/database-engine/availability-groups/windows/distributed-availability-groups?view=sql-server-ver17#improvement-to-distributed-ag-synchronization">reducing network saturation</a>, when the forwarder replica is in asynchronous commit mode. Distributed Availability Groups can now be replaced with distributed <a href="https://learn.microsoft.com/en-us/sql/database-engine/availability-groups/windows/contained-availability-groups-overview">contained availability groups</a>, allowing the master and msdb system databases to be in a contained DAG. This simplifies management by automatically replicating server-level objects between nodes, including logins and SQL Agent jobs. Customers frequently use Availability Groups and <a href="https://docs.aws.amazon.com/prescriptive-guidance/latest/patterns/migrate-sql-server-to-aws-using-distributed-availability-groups.html">Distributed Availability Groups to migrate</a> from on-premise to EC2 on AWS, between multiple regions within AWS, or leverage <a href="https://aws.amazon.com/blogs/modernizing-with-aws/extending-on-premises-ms-sql-server-always-on-availability-groups-to-amazon-ec2-for-disaster-recovery/">AWS as a DR site for their on-premise databases</a>. SQL Server 2025 distributed availability groups can help improve networking performance and ease operational burden for customers migrating to AWS or failing over between environments.</p> 
<p><strong>Optimized Database Operations and Performance</strong></p> 
<p>If you are offloading your application read-only workloads to Always On Availability Groups readable secondaries running on SQL Server 2025, you will find <a href="https://learn.microsoft.com/en-us/sql/relational-databases/performance/query-store-for-secondary-replicas?view=sql-server-ver17">new beneficial Query Store enhancements</a>, improving performance consistency. Query Store for readable secondaries are enabled by default in SQL Server 2025 providing more predictable query performance. Previously, temporary statistics were created on readable secondaries, but with SQL Server 2025 it is now sent back to the primary, persisted in the primary database, and sent back to the secondaries. This allows application read-only queries, executed against one secondary database host, to be distributed to all secondaries, providing consistent query performance across all read-only secondaries and the primary database. As you scale out your <a href="https://docs.aws.amazon.com/prescriptive-guidance/latest/patterns/configure-read-only-routing-in-an-always-on-availability-group-in-sql-server-on-aws.html">SQL Server on AWS readable secondaries</a>, which might require different CPU and memory configurations compared to your primary database, you can optimize your EC2 instance selection by <a href="https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instance-optimize-cpu.html">leveraging Optimize CPU</a>. This feature allows you to customize the number of vCPUs and/or disable hyperthreading of an instance’s CPU options to optimize the licensing costs of Microsoft Windows and SQL Server core-based licensing. Review the <em>Optimize CPU best practices for SQL Server workloads</em> <a href="https://aws.amazon.com/blogs/modernizing-with-aws/optimize-cpu-best-practices-for-sql-server-workloads/">original</a> and <a href="https://aws.amazon.com/blogs/modernizing-with-aws/optimize-cpus-best-practices-for-sql-server-workloads-continued/">continued</a> blogs for detailed performance and price/performance analysis.</p> 
<p>Database Administrators understand the importance of deploying tempdb according to best practice to increase performance and reduce tempdb contention. Customers running SQL Server on AWS typically leverage <a href="https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ssd-instance-store.html">Amazon EC2 instances with non-volatile memory express (NVMe) solid state drives (SSD)</a> instance store volumes, to <a href="https://docs.aws.amazon.com/prescriptive-guidance/latest/sql-server-ec2-best-practices/tempdb.html">increase tempdb performance</a> and isolate tempdb from runaway workloads. AWS provides a variety of SQL Server settings to <a href="https://docs.aws.amazon.com/prescriptive-guidance/latest/sql-server-ec2-best-practices/configure-tempdb.html">reduce tempdb contention</a> and optimize tempdb query performance in the <a href="https://docs.aws.amazon.com/prescriptive-guidance/latest/sql-server-ec2-best-practices/welcome.html">Best practices for deploying SQL Server on Amazon EC2</a> prescriptive guidance. A new SQL Server 2025 feature is <a href="https://learn.microsoft.com/en-us/sql/relational-databases/accelerated-database-recovery-concepts?view=sql-server-ver17#adr-improvements-in-sql-server-2025">Accelerated Database Recovery (ADR) in tempdb</a> which provides “instantaneous transaction rollback” and “aggressive log truncation”, allowing faster transaction rollback and reducing the chances of running out of tempdb transaction log space. Resource Governor can also be used with SQL Server 2025 to enforce the amount of <a href="https://learn.microsoft.com/en-us/sql/relational-databases/resource-governor/tempdb-space-resource-governance?view=sql-server-ver17">spaced used in tempdb by a specific workload group</a>. This can prevent runaway workloads from consuming excessive tempdb space, causing performance issues and a potential outage.</p> 
<p><strong>Developer Experience </strong></p> 
<p>SQL Server 2025 enhances its capabilities for integrating with external services, including REST/GraphQL endpoints and various AI services, through the <a href="https://learn.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/sp-invoke-external-rest-endpoint-transact-sql">stored procedure sp_invoke_external_rest_endpoint</a>. Using standard REST APIs, you can connect your SQL Server databases directly to AWS services without complex coding. This means you can use familiar SQL Server features alongside powerful AWS capabilities like <a href="https://docs.aws.amazon.com/apigateway/latest/developerguide/welcome.html">Amazon API Gateway</a>, <a href="https://aws.amazon.com/bedrock/">Amazon Bedrock</a>, <a href="https://aws.amazon.com/ecs/">Amazon ECS</a>, <a href="https://aws.amazon.com/lambda/">AWS Lambda</a>, <a href="https://aws.amazon.com/ec2/">Amazon EC2</a>, <a href="https://aws.amazon.com/s3/">Amazon S3</a>, <a href="https://aws.amazon.com/sqs/">Amazon SQS</a>, and <a href="https://aws.amazon.com/eventbridge/">Amazon EventBridge</a> to only name a few. The sp_invoke_external_rest_endpoint stored procedure payload can be formatted in JSON, XML, or TEXT and return payload can be up to 100MB in size. <a href="https://docs.aws.amazon.com/bedrock/latest/APIReference/welcome.html">Query Amazon Bedrock AI models</a> right from your database and unlock enhance data analysis, automate content generation, and scalable AI processing. If external rest endpoint is enabled, ensure proper access controls are configured to mitigate the risk of unauthorized access or transfer of data.</p> 
<p>SQL Server Reporting Services (SSRS), usually used to support on-premises reporting services, is&nbsp;<a class="c-link" href="https://learn.microsoft.com/en-us/sql/reporting-services/reporting-services-consolidation-faq" rel="noopener noreferrer" target="_blank">is being replaced by Power BI Report Server</a>&nbsp;starting with SQL Server 2025. Power BI Report Server offers a superset of features compared to SSRS. It can host traditional paginated reports (.rdl) like SSRS but also supports interactive Power BI reports (.pbix) and Excel files.&nbsp;SQL Server 2025 Power BI Report Server can be installed, configured, and&nbsp;<a class="c-link" href="https://learn.microsoft.com/en-us/power-bi/report-server/migrate-report-server" rel="noopener noreferrer" target="_blank">migrated from on-premises SSRS to AWS EC2</a>, taking advantage of the performance, security, and elasticity of AWS. Per Microsoft’s Product Terms, customers bringing their own SQL Server Enterprise Core or Standard Core licenses for SQL Server 2025 can deploy Power BI Report Server on a maximum number of vCPUs equal to the number of vCPUs they have licensed for SQL Server, subject to a licensing minimum of 4 cores or vCPUs. A Power BI Pro User SL is required to publish shared Power BI reports using the Power BI Report Server. Amazon EC2 provides a&nbsp;<a class="c-link" href="https://aws.amazon.com/ec2/instance-types/" rel="noopener noreferrer" target="_blank">wide selection of instance types</a>&nbsp;optimized to fit different use cases. EC2 instance types comprise a varying combination of CPU, memory, storage, and networking capabilities. Leverage the balance of compute and memory of a&nbsp;<a class="c-link" href="https://aws.amazon.com/ec2/instance-types/general-purpose/" rel="noopener noreferrer" target="_blank">General Purposes EC2 instance type</a>&nbsp;to run your Power BI Report Server, while the reporting and source SQL Server databases run on a&nbsp;<a class="c-link" href="https://aws.amazon.com/ec2/instance-types/memory-optimized/" rel="noopener noreferrer" target="_blank">Memory Optimized EC2 instance</a>&nbsp;designed to deliver fast performance for workloads that process large data sets in memory. For additional EC2 instance selection recommendations, use the&nbsp;<a class="c-link" href="https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/get-ec2-instance-type-recommendations.html#use-ec2-instance-type-finder-animation" rel="noopener noreferrer" target="_blank">AWS EC2 instance type finder</a>.</p>
